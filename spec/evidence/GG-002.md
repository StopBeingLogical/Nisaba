## What changed

| File | Change |
|---|---|
| `sync/itad.go` | ID resolution replaced with the bulk endpoint; `current.url` now written; the 500ms per-entry ticker deleted |
| `handlers/sync.go` | ITAD runs first as the authoritative provider; GG.deals runs second as a comparison source; an unset `itad.api_key` logs and continues instead of failing the run |
| `db/store.go` | `UpdateWishlistPricing` already carried `best_price_url`; unchanged |

`GG-001` addendum 2 established that the key's budget is 100 requests per
5 minutes (Bobby's app setup page) while the documented limit is 1000 — and no
limit is exposed in response headers. The old code's per-entry `GET
/games/lookup/v1` loop was ~609 requests for this wishlist, six times over. The
replacement is a single bulk endpoint:

```
POST /lookup/id/shop/61/v1      body: ["app/292030", "app/1091500", …]
                                →    {"app/292030":"018d937f-1212-…", …}
```

One request covers up to 100 Steam App IDs (`itadLookupChunkSize`), unknown IDs
come back `null` and are counted as not-found rather than parsed as an ID.

## Scorched earth (ruled 2026-09-16)

Run against the production copy first, and against Atlas in `DEPLOY-002` before
the first live sync — the delete is not code and never runs again:

```sql
DELETE FROM wishlist_price_history;                                   -- 18,335 rows
UPDATE wishlist_entries SET best_current_price=NULL, best_current_store=NULL,
       best_price_url=NULL, historical_low_price=NULL, historical_low_store=NULL,
```

Migrations must run before this SQL: `gg_deals_price` / `gg_deals_url` do not
exist until the new binary starts, and the statement fails to prepare otherwise
(`no such column: gg_deals_price`, hit on the copy before the deploy order was
corrected to migrate-then-scorch).

## What this does not fix

- 115 of the 609 resolved entries came back with an ID but no `current` block in
  the overview payload and stay unpriced. `NotFound` counts as 0 because ITAD
  resolved every ID; the absence is in the pricing data, not the lookup.
- Entries with no Steam App ID are untouched by both providers and still depend
  on the reseller scraper, which this task did not change.
