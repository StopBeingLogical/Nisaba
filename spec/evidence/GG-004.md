## The live sync

The app's only sync trigger is the authenticated full-sync button, and the live
`auth.secret` is not mine to use. Rather than touch auth, the same provider code
was built once as a one-off binary and run on the host against the production
database — the identical `storesync.SyncITADPricing` / `SyncGGDealsPricing` calls
the button makes, from the commit that was deployed:

```bash
$ GOOS=linux GOARCH=amd64 go build -o /tmp/nisaba-sync ./<harness> && rm -rf <harness>
$ scp /tmp/nisaba-sync truenas_admin@192.168.3.174:/mnt/MemoryAlpha/nisaba/nisaba-sync
$ sudo -n /mnt/MemoryAlpha/nisaba/nisaba-sync both /mnt/MemoryAlpha/nisaba/data/nisaba.db
  ITAD ID lookup 609/609
ITAD: updated=494 notfound=0 errors=0 err=<nil>
  GG.deals price fetch 609/609
GG.deals: priced=498 notfound=111 errors=0 err=<nil>
```

The harness is not in the repository (built from a throwaway directory, deleted
before the build finished), and the binary was removed from Atlas afterwards.
Two honest notes: the DB is written by a second process while the container
holds it open, which WAL plus `busy_timeout` handle and which produced no error;
and because the harness is not the HTTP handler, **this run is not in
`sync_log`** — the next button-driven full sync will be.
