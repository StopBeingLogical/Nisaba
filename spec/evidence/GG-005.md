## What changed

Two additive columns, per `contracts/database.md` (additive, idempotent, in
`runMigrations()`, existing rows never modified by the migration):

| File | Change |
|---|---|
| `schema.sql` | `wishlist_entries.gg_deals_price REAL`, `gg_deals_url TEXT` |
| `main.go` | the matching `ALTER TABLE … ADD COLUMN` statements |
| `db/models.go` | `GGDealsPrice`, `GGDealsURL` on `WishlistRow` and `WishlistDetailRow` |
| `db/store.go` | both SELECT lists + scans, and `UpdateWishlistGGDealsComparison(id, price, url)` |
| `sync/ggdeals.go` | writes only the comparison columns; `applyGGDealsPrice` became `applyGGDealsComparison` |

The price written is the lower of the `currentRetail` and `currentKeyshops`
figures GG.deals returns; the shop behind it is deliberately not recorded,
because the callout claims only that a cheaper price exists. Historical low is
no longer taken from GG.deals at all — ITAD own it.

## GG.deals cannot overwrite ITAD's columns — measured, not asserted

The isolation is the single claim worth testing rather than reading off the
diff, so the GG.deals pass was re-run against an already-synced copy and the
six ITAD-owned columns were compared row for row:

```bash
$ sqlite3 -csv -noheader nisaba.db "SELECT id,best_current_price,best_current_store,
    best_price_url,historical_low_price,historical_low_store FROM wishlist_entries
    ORDER BY id;" > itad_before.csv

$ <harness> gg nisaba.db            # GG.deals pass only, no ITAD call
GG.deals: priced=498 notfound=111 errors=0 err=<nil>

$ diff itad_before.csv itad_after.csv
IDENTICAL — 667 rows compared

history rows before: 494     history rows after: 494
gg_deals_price: 498          current_price: 494
```

All 667 wishlist rows identical across ITAD's price, storefront, deal URL,
historical low and history count. The comparison pass adds its own numbers and
touches nothing else.

## Coverage

```
GG.deals: priced=498 notfound=111 errors=0
```

498 of the 609 Steam-linked entries have a GG.deals price; 111 are absent from
GG.deals entirely, which is the expected shape — ITAD tracks 34 shops, GG.deals
covers a different, partly wider set, and an entry with no GG.deals listing
simply has no comparison (the callout stays hidden).

How many entries the callout will actually reach after the live sync:

```sql
SELECT COUNT(*) FROM wishlist_entries
WHERE gg_deals_price IS NOT NULL AND best_current_price IS NOT NULL
  AND gg_deals_price < best_current_price;
-- 284
```
